# Round 1 — Foundation & Core Product

## Current Product State
Greenfield → working product. Octavia is installable, demonstrable and testable end to end: a user can register, complete onboarding (EN/DE + starter content), create versioned prompts, build benchmarks through the wizard, launch evaluation/optimization runs against them, inspect every evolution step with per-case/per-criterion detail, and browse/install/publish marketplace items.

## Problems Identified
- No product existed; everything below was built from zero.
- LLM access requires credentials we don't have — would normally block all engine work and testing.
- Prompt tooling typically hides optimization internals; users can't audit "why did step 5 fail".
- Generic Laravel starter UI would undermine commercial credibility.

## Product Opportunities
- The step-by-step run timeline IS the differentiator — it got flagship layout treatment.
- Marketplace creates network effects: benchmarks are reusable assets, not one-off configs.
- Onboarding with genuinely runnable starter content turns "empty app" into "first win in 60 seconds".

## Technical Opportunities
- Deterministic mock LLM provider unblocks dev/CI/demos without keys (ADR-001).
- Queue-backed runs allow sync mode locally and worker mode in production without code changes.

## Selected Goals
1. Solid domain schema for prompts/benchmarks/runs/results with proper relations (no JSON-blob shortcuts).
2. Bomb-proof evaluation + evolution engine, fully tested.
3. Custom design system + complete app shell (auth, dashboard, settings) — zero starter-kit UI.
4. Core workflows complete in UI: prompts, benchmark wizard, runs, marketplace, settings.
5. EN/DE i18n from day one, landing page with SEO fundamentals, docs suite.

## Implementation Summary
- **Schema**: prompts+versions (current_version_id FK), benchmarks+cases+criteria (typed rows), benchmark collections, runs+steps+case_results+criteria_results (append-only history), marketplace_items. Indexes on FKs and hot paths.
- **Engine**: EvaluationService (pure scoring; contains/not_contains/regex local, llm_judge via provider protocol `SCORE: <float>`), EvolutionService (hill-climbing; best-tracking before target check; stale counter; mutation proposals persisted as separate steps; winning prompt promoted to new PromptVersion), ProcessRunJob (single queued entry point, graceful failure onto run record).
- **LLM layer**: contract + MockLlmProvider (documented behavior contract; judge/optimizer/task modes keyed by markers) + OpenAiCompatibleProvider + LlmManager (config-driven).
- **Web**: custom auth controllers over Laravel's password broker/guards; onboarding action seeds runnable starter content; policies for prompt/benchmark/run; settings incl. session listing; marketplace install = transactional deep-copy between users.
- **Frontend**: Tailwind v4 theme tokens (ink/paper/violet/signal), O* component library, three layouts, 15 pages, vue-i18n EN/DE, Inertia progress + flash handling.
- **SEO/marketing**: landing page with real feature copy (nothing advertised that doesn't exist), legal pages, JSON-LD, OG tags, robots.txt, sitemap.xml.

## Tests / Validation
- Pest: **21 tests / 72 assertions green** — engine semantics (scoring types, regex validation, full climb-to-target run with version promotion, no-benchmark failure) + web layer (auth flows, guest redirects, onboarding seeding, cross-user isolation, strict benchmark validation, run queuing) + marketplace (publish/install deep-copy for prompts and benchmarks, validation).
- Post-review fixes surfaced by the browser pass and new tests: marketplace publish had no UI trigger (added buttons to prompt/benchmark pages); `MarketplaceItem::$fillable` missing publisher/title/relation ids caused publish 500s.
- Pint clean, vue-tsc clean, production build green (372 KB JS / 57 KB CSS).
- Browser smoke test (real Chromium): register → onboarding in German → dashboard → open starter prompt → launch optimize run → completed at 100% target with visible step detail. Fixed issues found during smoke: missing enum cast, missing authorize traits, i18n placeholder format, blade template asset bug, zombie dev server serving stale routes.

## Design Review
