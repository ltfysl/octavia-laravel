# Round 14 — Team Workspaces

## Current Product State
Thirteen rounds in. The product was single-user only. This round introduced the foundational collaboration layer: teams with roles and team-aware visibility for prompts/benchmarks.

## Selected Goals
1. `Team` + `TeamMember` models with owner/admin/member roles.
2. CRUD UI for teams (create, view members, invite, remove, delete).
3. Team-aware visibility: prompts/benchmarks from team mates appear in each other's libraries via `scopeVisibleTo`.

## Implementation Summary
- **Schema**: `teams` (owner FK, name) + `team_members` pivot (team FK, user FK unique per pair, role enum string). Indexed by user_id.
- **Model**: `Team::hasMember()`, `roleOf()`, `users()` belongsToMany; `User::ownedTeams()`, `teamMemberships()`, `teamMateIds()` (returns all users sharing ≥1 team, including owners).
- **Visibility**: `scopeVisibleTo` on Prompt/Benchmark now uses `whereIn('user_id', $user->teamMateIds())` — team mates see each other's private items; outsiders still don't.
- **Controller**: `TeamController` — index/store/show/invite/removeMember/destroy. Owner can delete team; members can leave themselves; only owner/admins can invite. Invite validates email exists in users table.
- **UI**: `/teams` index (grid cards, create form) + `/teams/{id}` detail (member list, invite form). Admin sidebar gains Teams link.
