# Round 6 — Localized Verification & Usage Quotas

## Current Product State
Five rounds in: full core product, notification system with preferences, API v1, admin, verification flow. This round fixed the last i18n gap (verification mail) and introduced the first usage-control mechanism (daily run quota) — groundwork for the credits-based billing model.

## Problems Identified
- DE users received the verification mail in English: the framework's VerifyEmail notification pre-translates its lines before any locale switch.
- Nothing limited run creation; a single user could fire unlimited LLM-costly runs.

## Selected Goals
1. Custom `VerifyEmailNotification` building every line with the recipient's stored locale.
2. Per-user daily run quota, config-driven, enforced server-side with HTTP 429.

## Implementation Summary
- **VerifyEmailNotification**: subclass of the framework notification overriding `buildMailMessage($url)` (matching the parent signature — the first attempt without the `$url` param fataled). All lines translated with `User::preferredLocale()`. `User::sendEmailVerificationNotification()` now sends the localized variant.
- **Run quota**: `runs` rate limiter (`Limit::perDay(config('llm.run_quota_per_day'))` keyed by user id) applied to both `POST /runs` (web) and `POST /api/v1/runs`. Config: `OCTAVIA_RUN_QUOTA_PER_DAY` (default 50), documented in `.env.example`.
- New lang keys `auth.verify.*` (EN/DE) for the localized verification mail.

## Tests / Validation
- **55 Pest tests / ~186 assertions green**. Added:
  - Quota: 429 after N runs (config-driven), per-user isolation (user B unaffected by user A's exhausted quota).
  - Verification: localized mail asserted via the new notification class, resend throttle, signed-link verify, tampered-link rejection.
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.

## Bugs Fixed During Review
- `buildMailMessage()` signature mismatch with the parent (missing `$url`) — fatal on registration.
- `preferredLocale()` returned null for freshly created users whose model attributes didn't hydrate the DB default — guarded with `?? config('app.locale')`.
- `config/llm.php` structure corrupted during an edit — restored and linted.

## Design Review
No UI changes. The 429 response is a plain HTTP status for now; the frontend surfaces it as a generic error. A friendly quota-exhausted state belongs to the future billing UI.

## Remaining Problems
- Quota is hard-limited; no soft warning as users approach it (belongs with billing UI).
- VerifyEmail mail content is now localized, but password-reset mail remains framework-default (English).

## Human Actions Required
Unchanged: OpenAI-compatible key, production domain/TLS, Stripe account when billing starts.
