# Round 7 — Localized Reset Mail & Soft Quota Warning

## Current Product State
Six rounds in. The product is functionally complete across its value chain; this round closed the last two i18n gaps in transactional mail and added the soft half of the quota system (hard 429 existed since round 6).

## Problems Identified
- DE users received the password-reset mail in English — same framework i18n issue as the verification mail (fixed in round 6).
- The daily run quota was invisible until it hard-blocked with a 429. No warning as users approach it.

## Selected Goals
1. Localized password-reset mail, following the established VerifyEmailNotification pattern.
2. Quota state shared to the frontend + soft warning banner at ≥ 80% consumption.

## Implementation Summary
- **ResetPasswordNotification**: subclass of the framework notification, overriding `resetUrl()` (preserving the framework's `createUrlCallback` hook) and `buildMailMessage($url)`. All lines translated with `User::preferredLocale()`. `User::sendPasswordResetNotification()` sends the localized variant — the password broker picks it up automatically.
- **Quota prop**: `HandleInertiaRequests` shares `runQuota = { used, limit }` (`RateLimiter::attempts` keyed by user id). AppLayout shows an amber banner when consumption reaches 80%.
- New lang keys: `auth.reset.*` (EN/DE), `runs.quotaWarning` (EN/DE).

## Tests / Validation
- **59 Pest tests / 212 assertions green**. Added:
  - Reset mail: localized German subject, token-bearing action URL, end-to-end reset flow (old password rejected, new accepted).
  - Quota prop: shared with authenticated users, reflects consumed attempts.
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.

## Design Review
Quota banner reuses the amber attention tone from the verification banner — same visual grammar for "action recommended". Both banners stack cleanly (flex-wrap).
