# Round 3 — Depth, Notifications & Hardening

## Current Product State
Rounds 1–2 delivered the full core product plus playground, collections, API v1 and admin. The app is feature-complete for its value proposition; this round focused on retention (completion mails), version-history depth (diffs), and security hardening.

## Problems Identified
- Optimize runs take minutes; users wander off and never learn the result — a retention gap.
- Version history exists but shows raw content only; users cannot see *what changed* between versions.
- No brute-force protection on credential endpoints; no baseline security headers.
- Landing page hero wrapped to 3 lines at desktop width; sections felt cramped at large viewports.

## Selected Goals
1. Word-level diff view between any prompt version and the current one.
2. Localized run-completion email (DE/EN by user preference).
3. Rate limiting on all credential endpoints + security headers middleware.
4. Landing polish: wider hero (2-line rule), cinematic section spacing, hover physics, staggered scroll reveals — honoring `prefers-reduced-motion`.

## Implementation Summary
- **Diff**: `resources/js/utils/diff.ts` — dependency-free LCS word diff with line-level fallback beyond 1500 tokens; `ODiff.vue` renders add/remove marks with +/− word-count badges; "Compare with current" toggle in the versions tab.
- **Notification**: `RunCompletedNotification` (mail) sent when optimize runs complete; branded markdown template (`mail/run-completed`) with score/target/benchmark table and CTA. Locale resolution: `User::preferredLocale()` → explicit `__($key, $replace, $locale)` translation in both subject and blade (app locale is never mutated). Evaluate runs do not notify.
- **Security**: `auth` rate limiter (5/min per email+IP) on register/login/forgot/reset POSTs; `SecurityHeaders` middleware (X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy) appended to the web group.
- **Landing polish** (per design review): H1 container widened to `max-w-5xl` (measured: 1024px wide, 2 lines at 1440×900), sections bumped to `py-24 md:py-32`, hover physics (lift + shadow + icon color swap) on mock and feature cards, staggered `v-reveal` IntersectionObserver directive (no new dependency) that never hides content under `prefers-reduced-motion`.

## Tests / Validation
- **40 Pest tests / 141 assertions green** — added: notification sent w/ German subject for DE user, no notification for evaluate runs, security headers present, login throttling returns 429 after repeated failures.
- Playwright E2E: **7 passed** (landing changes verified against existing assertions).
- vue-tsc clean, Pint clean, production build green.
- Browser check: H1 measured at 1024px width / exactly 2 lines; reveal counts increase on scroll; screenshot reviewed.

## Design Review
The reveal pattern is documented as the single sanctioned motion primitive — subtle settle-in, no bounce, no parallax. Hover physics limited to lift + border/shadow transitions; consistent with the calm-instrument identity. Diff marks reuse signal colors (mint = added, rose = removed).
