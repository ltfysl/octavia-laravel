# Round 11 — Snapshot Versioning & Welcome Mail

## Current Product State
Ten rounds in. The marketplace install previously copied the *live* source — if a publisher edited their prompt/benchmark after publishing, every future install silently changed. This round fixed the versioning semantics and added the welcome touchpoint.

## Problems Identified
- Marketplace installs tracked the live source: published listings mutated retroactively when the publisher edited their item. Violates the "mit versionierung" requirement.
- No welcome touchpoint after onboarding.

## Selected Goals
1. Freeze a snapshot at publish time; install from the snapshot.
2. Localized welcome mail after onboarding completes.

## Implementation Summary
- **Prompt snapshots**: publish stores `snapshot.content` = the current version's content at publish time.
- **Benchmark snapshots**: publish stores category + full case/criteria tree in `snapshot`.
- **Install**: prefers the frozen snapshot (prompt → single version with published content, changelog "Installed from marketplace vN"; benchmark → cases/criteria reconstructed from snapshot). Falls back to the live source only for legacy listings without a snapshot.
- **WelcomeNotification**: localized markdown mail sent on onboarding completion, pointing to the dashboard/first run.

## Tests / Validation
- **76 Pest tests / 259 assertions green**. Added:
  - `SnapshotInstallTest` (3): snapshot frozen at publish; install yields snapshotted content even after source mutation; legacy no-snapshot fallback still works.
  - Welcome mail test: localized German subject asserted.
  - Existing prompt-install test updated to new semantics (single frozen version).
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.

## Design Review
No UI changes; semantics-only round.

## Remaining Problems
- Republishing bumps the listing version and refreshes the snapshot — but buyers who already installed keep their copy (by design). A "update available" indicator is a future enhancement.
