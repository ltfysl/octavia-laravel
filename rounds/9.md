# Round 9 — Marketplace Abuse Reports

## Current Product State
Round 8 gave admins unlist/relist powers but no signal for *why* — users had no way to flag a listing. This round closed the loop: report → queue → moderation action.

## Problems Identified
- No user-facing mechanism to report inappropriate/spam/copyright-violating listings.
- Admin moderation was blind: no reports to act on.

## Selected Goals
1. Authenticated, rate-limited, deduplicated report flow on marketplace cards.
2. Admin reports queue with two resolution actions: dismiss (report only) and unlist-and-resolve (report + hide item).

## Implementation Summary
- **Schema**: `marketplace_reports` — item FK (cascade), reporter FK (cascade), closed reason set (`inappropriate|spam|copyright|broken|other`), optional message, status (`open|resolved`), resolver actor/timestamp. Unique `(item, reporter)` prevents duplicate spam clicks; indexed by status+created_at.
- **Endpoint**: `POST /marketplace/{item}/report` (auth, throttle 10/min). UpdateOrCreate semantics against *open* reports only — a resolved report stays as history and a new one opens. Unlisted items reject reports (404).
- **UI**: ⚑ button per marketplace card toggles an inline form (reason select + optional message). Success flash via existing session mechanism.
- **Admin**: `/admin/reports` lists open reports with reason badge, quoted message, reporter/publisher metadata; actions "Dismiss" and "Unlist item" (unlist hides the item and resolves the report with the acting admin recorded). Admin sidebar gains a Reports link.

## Tests / Validation
- **70 Pest tests / 244 assertions green**. Added 4:
  - Guest redirect to login.
  - Invalid reason rejected.
  - Report created once per user (dedup), latest message kept.
  - Admin sees open reports; unlist-and-resolve hides item + records resolver; dismiss leaves listing untouched.
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.

## Bugs Fixed During Review
- `MarketplaceReport::$fillable` initially missing `status/resolved_by/resolved_at` — resolve silently did nothing (caught by test).
- Test helper iterated an assoc array incorrectly (`string + array` TypeError) — rewritten.
- Dedup semantics refined: resolved reports are history, so re-reporting opens a fresh one instead of resurrecting a resolved row.

## Design Review
Report UI is deliberately quiet: ink-300 ⚑ that turns rose on hover — reporting must be discoverable but not alarming. Admin queue uses rose badges for reason and the standard admin-table grammar.
