# Round 2 — Product Depth: Playground, Collections, API, Admin

## Current Product State
Round 1 delivered the core product (benchmarks, evolution engine, runs, marketplace, auth, i18n, landing). This round deepened the product on four fronts: ad-hoc experimentation, multi-benchmark workflows, a public API surface, and internal operations tooling.

## Problems Identified (Product Discovery)
- Users cannot test prompt tweaks without committing a full run — friction in the iterate loop.
- Benchmarks are single suites; companies want to throw several at one prompt (explicit in the original brief).
- No programmatic access blocks CLI tools, integrations and automation — the "API readiness" requirement.
- Operators have no way to see or manage users; commercially unusable without it.

## Selected Goals & Implementation Summary
1. **Playground** (`POST /prompts/{id}/playground` + UI panel on prompt editor)
   - Runs current *or unsaved* prompt content against a single input via `RunPlayground` action. No DB writes.
   - `LlmProvider` interface bound in container to the configured default provider.
2. **Benchmark collections**
   - `CollectionController` (create/update/delete) with owner-scoped benchmark validation (`Rule::exists ... where user_id`).
   - Run creation now accepts `collection_id` XOR `benchmark_id`; collection runs evaluate every contained suite.
   - New `/collections` page + sidebar nav entry; EN/DE strings.
3. **Public API v1** (`routes/api.php`, Sanctum)
   - Token issuance (6/min throttle), prompts CRUD-read, synchronous evaluate endpoint, runs start/show/cancel with ownership enforcement.
   - JSON API Resources (`PromptResource`, `BenchmarkResource`, `RunResource`) with conditional content loading.
4. **Admin panel** (`/admin`, `EnsureUserIsAdmin` middleware, `is_admin` flag shared to frontend)
   - Platform stats (users/prompts/benchmarks/runs incl. active+failed), newest users, latest runs.
   - User management: search, pagination, promote/demote admin (self-protection), delete user (self-deletion blocked).
   - Sidebar shows Admin link only for admins.

  - `AdminTest` (4): guest redirect, non-admin 403, admin views, toggle/self-protection, delete protection.

## Bugs Fixed During Review
- `BenchmarkCollection::benchmarks()` pivot keys needed explicit naming (`collection_id`) — Laravel's default derivation didn't match the migration.
- `MarketplaceItem::$fillable` was missing publisher/title/relation ids → publish 500s (found by new tests).
- Missing enum cast on `Prompt.visibility` and authorize traits on the base controller (from round 1 smoke findings, regression-tested).

## Design Review
Playground panel follows the two-pane editor layout; output renders as mono artifact block consistent with run steps. Admin pages intentionally reuse app chrome with noindex headers — internal tooling, minimal bespoke styling.

## Remaining Problems
- Email verification still soft; billing not started; teams not modeled.
- API has no per-token scopes yet (all-or-nothing tokens).

## E2E Suite (added at end of round)
`npx playwright test` — 7 tests, all green: register → DE onboarding → dashboard → prompt library → optimize run completes with step timeline → playground output → publish/marketplace listing, plus the public landing page. Runs against a dedicated `octavia_e2e` MySQL database wiped by global setup; a Playwright setup project registers the user and shares the authenticated session with dependent tests.

Isolation guarantee: `e2e/server-router.php` forces `DB_DATABASE=octavia_e2e` + `QUEUE_CONNECTION=sync` via `putenv` *before* the framework boots (Dotenv is immutable, so these win over `.env`), and the built-in server runs with `-t public` so hashed assets serve. An earlier attempt that relied only on `webServer.env` silently ran E2E against the dev database — caught by a post-run DB diff and cleaned up (`scripts/clean-e2e-pollution.php`, since removed).
