# Round 19 — Credits & Billing Foundation

## Current Product State
Eighteen rounds in. All core workflows complete. The top backlog item was billing — the credits model fits usage-based LLM costs (steps, not seats), so this round built the full credit foundation with a Stripe-ready seam.

## Selected Goals
1. Credit ledger + balance (`CreditService`) with atomic consume and full audit trail.
2. Gate run starts on credits: reserve `max_steps` up front, refund unused steps on any terminal state.
3. User-facing billing page (balance + recent transactions).
4. Public localized `/pricing` page (Free vs Pro, honest "coming soon" for paid).
5. Stripe env placeholders + operations doc with launch checklist.

## Implementation Summary
- **Migration**: `users.credits_balance`, `credit_transactions` ledger (user FK, delta, reason, meta JSON, indexed by user+date).
- **`CreditService`**: grant/grantSignup/consume; consume uses conditional `decrement WHERE balance >= amount` so concurrent runs cannot overdraw.
- **`RunObserver`**: on terminal status transition, refunds `reserved − executed` steps. Centralized so completed/failed/cancelled settle identically.
- **`RunController::store`**: reserves 1 credit (evaluate) or max_steps (optimize); insufficient balance → validation error with localized message, no run created.
- **Registration** grants the signup credit (config: `OCTAVIA_SIGNUP_CREDITS`, default 100). UserFactory mirrors it so tests/users can start runs.
- **UI**: `/settings/billing` (balance card + transaction history, mint/ink delta colors); sidebar footer Billing link (desktop + mobile). `/pricing` now renders a dedicated page instead of reusing Landing.
- **Fixed latent bug**: `/settings` nav link had no route → now redirects to profile.
