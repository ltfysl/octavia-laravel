# Round 13 — Republish Notifications for Installed Users

## Current Product State
Round 12 added install tracking and update-available badges, but users had to actively check the marketplace to learn about updates. This round pushes the signal to them.

## Selected Goals
1. Notify every user with a tracked install (version lags behind) when a publisher republishes at a new version.

## Implementation Summary
- **Publish flow**: after `updateOrCreate`, queries `marketplace_installs` where tracked version < new item version and user ≠ publisher. Sends `ListingUpdatedNotification` (database channel → bell + notifications index page) to each.
- The fragile `wasChanged('version')` approach was replaced with an explicit install-version comparison — more robust because it directly encodes "your installed copy is behind" regardless of model state subtleties.
- **Bug fixed**: initial implementation used `wasChanged('version') && version > getOriginal('version')`, which failed in tests due to model-state subtleties after `updateOrCreate`. Replaced with direct lagging-install query.
