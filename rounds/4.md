# Round 4 — Notification Center & Preferences

## Current Product State
After round 3 the product had localized completion mails, diff views, API v1 and admin tooling. This round turned the one-way mail into a full notification system: in-app feed with unread badge, mark-read flow, and a user-facing mail opt-out.

## Problems Identified
- Completion mails existed, but users had no in-app visibility and no way to silence the mails.
- No persistence for notifications meant no history and no unread state.

## Selected Goals
1. Database notification channel for run completion.
2. Bell + dropdown in the app shell: unread badge, recent feed, click-through to runs, mark-read on open.
3. Mail opt-out preference persisted per user, editable in settings, respected in the notification `via()`.

## Implementation Summary
- **Schema**: `notifications` table (Laravel standard) + `users.notify_run_completed_mail` boolean (default true).
- **Notification**: `via()` now returns `['mail', 'database']` by default, `['database']` when opted out — the database entry always lands so the bell stays accurate even with mails off. Database payload carries run id/name/status/score for direct rendering.
- **App shell**: `HandleInertiaRequests` shares a `notifications` prop (unread count + last 6 items); `AppLayout` renders a bell with unread badge, dropdown listing runs (click-through to run detail), and a `POST /notifications/mark-read` call on open.
- **Settings**: checkbox in profile form ("Completion emails"), persisted through `updateProfile` (boolean validation, `sometimes` so absent keeps stored value).
- **Dev scripts**: `scripts/seed-run.php` + `scripts/seed-notification.php` for quick manual bell testing (removed after verification).

## Tests / Validation
- **45 Pest tests / 154 assertions green**. Added:
  - Database notification lands with run payload; mark-read empties unread feed.
  - `via()` includes mail by default, omits it when opted out (direct channel assertion).
  - Settings persist the preference; invalid locale/flag rejected.
  - Existing localized-mail tests still pass (mail respects opt-out implicitly via `via()`).
- Playwright E2E: 7 passed. vue-tsc clean, Pint clean, build green.
- Browser verification: seeded notification → badge shows "1" → opening the bell marks read → badge cleared after navigation.

## Bugs Fixed During Review
- `via()` originally used an untyped `object` + a `locale()` override that broke `Notification::locale()` compatibility — replaced with `preferredLocale()` on the User model and typed `User` params.
- Bell initially used a `@toggle` handler that never fired reliably in headless Chromium; replaced with a click handler on the summary (idempotent: mark-read on every open).
- `ProcessRunJob::dispatch()` requires the int id — dev seed script fixed accordingly.

## Design Review
Bell follows the app-shell restraint rules: 8×8 icon button, violet badge only when unread > 0, dropdown = compact list with mono score, click-through to runs. No new components needed; details/summary dropdown pattern matches the existing mobile nav.

## Remaining Problems
- No per-notification delete; feed capped at 6 items (older silently dropped from view, still in DB).
- Notification preferences UI covers only the completion mail — future channels (webhooks) need a preferences matrix.
