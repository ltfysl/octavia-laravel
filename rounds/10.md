# Round 10 — Notification Center & Reporter Feedback Loop

## Current Product State
Nine rounds in. The bell showed only the last 6 notifications with no full history and no per-item management beyond delete. Report resolution was invisible to the reporter.

## Selected Goals
1. Full notification center: paginated index page with mark-unread, delete, and mark-all-read.
2. Close the moderation loop: reporters get a bell notification when their report is resolved.

## Implementation Summary
- **Index page** (`/notifications`, `NotificationController@index`): paginated feed (20/page) rendered as a table with unread highlight, status badges, score, per-item mark-unread and delete, plus mark-all-read in the header. Bell dropdown links to it.
- **Mark-unread endpoint**: `POST /notifications/{id}/unread`.
- **Reporter loop**: `MarketplaceReportResolvedNotification` (database channel → bell + index page) fired on every resolution, carrying item title and outcome (`kept` / `unlisted`).
- Shared `notifications` prop falls back to `data.item_title` so report-resolved entries render correctly next to run completions.

## Tests / Validation
- **72 Pest tests / ~250 assertions green**. Added:
  - ReportResolutionTest (2): reporter notified on resolve with outcome payload; resolver actor recorded.
  - RunQuotaPropTest (2): quota prop shared and reflects consumption.
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.
