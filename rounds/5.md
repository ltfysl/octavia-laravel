# Round 5 — Notification Management, Diff API & Email Verification

## Current Product State
Rounds 1–4 delivered the core product, playground, collections, API v1, admin and a notification bell with unread badge. This round completed notification management (per-item delete), exposed prompt diffs over the API, and closed the biggest security gap: unverified email addresses now get a persistent banner, resend flow and signed verification link.

## Problems Identified
- Bell notifications could only be bulk-cleared — no per-item control.
- The diff engine existed only in the frontend; API clients had no access to version comparisons.
- `email_verified_at` was dead weight: no mail was ever sent at registration, no banner, no verify route. The round-3 controller even called methods that didn't exist (`hasVerifiedEmail`) — a latent 500.

## Selected Goals
1. Per-notification delete scoped to the owner.
2. `GET /api/v1/prompts/{id}/diff?from=&to=` returning version contents for client-side diffing.
3. Full email verification flow: MustVerifyEmail on User, send-at-registration, resend endpoint (throttled), signed verify route, dismiss-on-success banner in the app shell.

## Implementation Summary
- **Notification delete**: `DELETE /notifications/{id}`, owner-scoped (foreign ids match nothing). Bell items render an inline delete button; run links remain clickable.
- **Diff API**: returns `from`/`to` version + content; defaults to last-two versions; explicit `from`/`to` query params validated; single-version prompts → 422, foreign prompts → 404. Computation stays client-side (`utils/diff.ts`).
- **Verification**: User implements `MustVerifyEmail`; `RegisteredUserController` triggers the mail via the framework's Registered-event listener; `routes/verification.php` adds resend (`throttle:6,1`) and signed verify routes; amber in-app banner shows until verified, hides after a successful resend.
- **Bug fixed**: `versions()` relation orders newest-first — the diff endpoint's chronological assumptions broke silently. Fixed by explicit ascending sort (and documented).

  - `EmailVerificationTest` (5): mail sent at registration, resend works, throttle 429, signed link verifies, unsigned/mismatched/foreign-id links rejected.

## Design Review
Banner uses the amber signal tone (attention without alarm) and sits above page content, not fixed — it disappears permanently once verified or after a successful resend. Bell delete buttons are quiet (ink-300 → rose on hover) to avoid competing with the primary click-through.
