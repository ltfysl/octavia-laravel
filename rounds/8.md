# Round 8 — Token Abilities & Marketplace Moderation

## Current Product State
Seven rounds in. The API v1 existed with all-or-nothing tokens; the marketplace had no moderation path — a published item stayed published forever with no admin recourse. This round added both governance primitives.

## Problems Identified
- Sanctum tokens carried `['*']` unconditionally: an integration token could do everything, including future endpoints it was never granted.
- No moderation: an abusive or low-quality marketplace listing could only be removed by editing the database directly.

## Selected Goals
1. Token abilities (`read` / `write`) issued at token creation and enforced on write/evaluate endpoints.
2. Admin marketplace moderation page: unlist/relist any listing without deleting the underlying prompt/benchmark.

## Implementation Summary
- **Token abilities**: `POST /api/v1/auth/token` accepts `abilities` (validated against the closed set `read|write`, defaulting to `['read']`). `abilities:write` middleware on prompt store, evaluate, run store/cancel; `abilities:read` on evaluate. Unknown ability names rejected at issuance so tokens can't silently gain future permissions. Sanctum aliases registered in `bootstrap/app.php`.
- **Moderation**: `Admin\MarketplaceController` with `GET /admin/marketplace` (last 50 items, listed-first) and `POST /admin/marketplace/{item}/listed`. Unlisting nulls `published_at` (hidden from public listing + uninstallable); relisting restores. Underlying prompts/benchmarks untouched. Admin sidebar gains a Marketplace link.
- **Tests rewritten**: ApiV1Test migrated to `Sanctum::actingAs($user, $abilities)` pattern (plain `actingAs('sanctum')` leaves `currentAccessToken()` null → 401 under CheckAbilities).

## Tests / Validation
- **66 Pest tests / 229 assertions green**. Added:
  - Ability issuance validation (unknown ability rejected).
  - Read-only token blocked on prompt create (403) and run create (403), nothing persisted/dispatched.
  - Write+read token full flow still works.
  - Moderation: non-admin 403, admin listing view, unlist→relist cycle, install blocked while unlisted → restored after relist.
- Playwright E2E: 7 passed. Pint clean, vue-tsc clean, build green.

## Design Review
Admin marketplace table follows the established admin-table grammar (users page). Unlisted state uses the neutral badge vs mint "listed" — consistent signal-color semantics.

## Remaining Problems
- Ability model is binary read/write; finer-grained scopes (per-resource) belong with billing tiers.
- Moderation is reactive only — no user-facing report flow yet (backlog).
